# SIPL Language Toolkit — Курсовий проєкт з дисципліни «Теорія програмування»

[![SIPL Toolkit CI](https://github.com/USERNAME/sipl-toolkit/actions/workflows/ci.yml/badge.svg)](https://github.com/sipl-knu-org/sipl-toolkit/actions/workflows/ci.yml)

Проєкт являє собою модульний набір інструментів (**Language Toolkit**) для модельної імперативної мови програмування **SIPL** (*Simple Imperative Programming Language* / *Structured Imperative Programming Language*), яка використовується в курсі «Теорія програмування» для формалізації синтаксису, композиційно-номінативної семантики та верифікації програм.

## 2. Короткий звіт про виконану роботу

### 2.1. Формалізація синтаксису та типізоване AST (`CORE-01`, `CORE-02`)
1. **Формальна граматика (`grammar/sipl.lark`):** розроблено однозначну LALR-граматику мови SIPL на основі базової БНФ із Практичної роботи №1 (правила `NP1`, `NS1–NS6`, `NA1–NA6`, `NB1–NB5`, `NV`, `NN`).
2. **Усунення неоднозначності БНФ:** відповідно до підручника М. С. Нікітченка (розділ 1.2, с. 10), неоднозначність синтаксичного аналізу виразів і операторів усунено шляхом фіксації лівої асоціативності бінарних операцій та ієрархії пріоритетів (від найвищого до найнижчого):
   * `1)` множення та ділення (`*`, `×`, `div`, `mod`);
   * `2)` додавання і віднімання (`+`, `-`);
   * `3)` операції порівняння (`=`, `>`, `>=`, `<`, `<=`);
   * `4)` заперечення (`¬`, `!`, `not`);
   * `5)` диз'юнкція (`∨`, `||`, `or`);
   * `6)` присвоювання (`:=`);
   * `7)` оператор циклу (`while ... do ...`);
   * `8)` умовний оператор (`if ... then ... else ...`);
   * `9)` послідовне виконання (`;`).
3. **Типізоване AST та діагностика (`src/sipl/ast.py`, `src/sipl/parser.py`):** всі синтаксичні категорії мови (`Prog`, `Stm`, `Aexp`, `Bexp`, `Var`, `Num`) представлені незмінними (`frozen=True`) вузлами `dataclass`, кожен із яких зберігає точні координати у вихідному тексті (`SourceSpan`: рядок, колонка, зсув). У разі синтаксичної помилки формується об'єкт `Diagnostic` із кодом `SIPL-SYNTAX-ERR`, вказівником на місце помилки та підказкою щодо її виправлення.

### 2.2. Інтерпретатор композиційної семантики та трасування (`CORE-03`, `CORE-04`)
1. **Алгебра даних та стан пам'яті (`State`):** стан змінних формалізовано як однозначне іменне дане $st \in State = Var \to Int$ із відображенням у нотації практикуму `[N ↦ 0, R ↦ 15, T ↦ 8]`. Реалізовано бінарну операцію накладання («накладку») $\nabla$ (`State.overlay`), часткову функцію розіменування $x\Rightarrow(st) = st(x)$ за формулою `AF_DNM` (`State.deref`), відношення розширення станів $st \subseteq st'$ (`State.is_substate_of`), параметричну константу $\overline{n}$ та тотожну функцію $id$ (`AF_ID`).
2. **Обчислення композицій програмної алгебри $A_{SIPL}$ (`Interpreter`):**
   * арифметичні вирази (`FA: State → Int`) та умови (`FB: State → Bool`) обчислюються через композицію суперпозиції $S^n$ (`AF_S`);
   * оператори (`FS: State → State`) реалізують біномінативні функції-перетворювачі станів за формулами присвоювання $AS^x$ (`AF_AS`), послідовного виконання $\bullet$ (`AF_SEQ`), розгалуження $IF$ (`AF_IF`), циклу $WH$ (`AF_WH` із підрахунком кількості ітерацій `NumItWH`) та `skip` (`AF_ID`).
3. **Контроль частковості та зациклювання:** при зверненні до неініціалізованої змінної генерується помилка невизначеності `UndefinedVariableError` (`SIPL-UNDEFINED-VAR`), при діленні на нуль — `DivisionByZeroSIPL` (`SIPL-DIV-ZERO`), а при перевищенні ліміту кроків `max_steps` — `StepLimitExceededError` (`SIPL-STEP-LIMIT`).
4. **Подієва модель (`trace`):** під час виконання програми генерується послідовність подій `BeforeStatement`, `AfterStatement`, `VariableChanged`, `ConditionEvaluated` та `ExecutionFinished` із фіксацією стану до/після кроку, назви правила алгебри (`AF_*`), проміжних станів циклу ($st_0, st_1, \dots$) та операції накладання $st \nabla [x \mapsto v]$.

### 2.3. Візуалізація дерева синтаксичного виводу (`VIS-01`)
Модуль `src/sipl/visualization/parse_tree.py` автоматизує виконання **Практичної роботи №1**:
* будує повне дерево синтаксичного виводу в термінах метазмінних курсу (`<програма>`, `<оператор>`, `<умова>`, `<вираз>`, `<змінна>`, `<число>`) із прив'язкою до номерів правил БНФ та фрагментів коду;
* виконує обхід листків дерева зліва направо з автоматичною нумерацією термінальних символів (`1 begin 2 R 3 := ...`) для перевірки синтаксичної коректності програми;
* експортує дерево у формати `Text` (псевдографіка), `JSON`, `Graphviz DOT` та автономний векторний `SVG`.

### 2.4. Автоматична побудова семантичного терму (`SEM-01`)
Модуль `src/sipl/semantics/terms.py` автоматизує побудову семантичного терму з **Практичної роботи №2**:
* реалізує рекурсивні відображення `sem_P: Prog → TFS`, `sem_S: Stm → TFS`, `sem_A: Aexp → TFA`, `sem_B: Bexp → TFB`;
* на кожному кроці фіксує застосоване правило заміни з Таблиці 1.6 (`NS_Prog`, `NS_Stm_As`, `NS_Stm_Seq`, `NS_Stm_If`, `NS_Stm_Wh`, `NS_Stm_BE`, `NS_Stm_skip`, `NS_A_Num`, `NS_A_Var`, `NS_A_Add`, `NS_A_Sub`, `NS_A_Mult`, `NS_A_Par`, `NS_B_eq`, `NS_B_gr`, `NS_B_or`, `NS_B_neg`, `NS_B_Par`);
* повертає покроковий протокол виведення (`steps`), фінальний семантичний терм в Unicode-нотації курсу та готовий код у форматі $\LaTeX$.

### 2.5. Консольний інтерфейс та інженерна інфраструктура (`CORE-05`, `REL-01`, `REL-02`)
* Утиліта `sipl` (`src/sipl/cli.py`) об'єднує всі інструменти ядра в єдиний CLI з підтримкою команд `parse`, `check`, `run`, `trace`, `term`, `visualize` та прапорця `--json` для інтеграції із зовнішніми клієнтами.
* Налаштовано автоматичний пайплайн GitHub Actions (`.github/workflows/ci.yml`), який перевіряє стиль коду (`ruff`), запускає 48 тестів із контролем покриття ($\ge 85\%$) та збирає дистрибутив пакета на Python 3.11 і 3.12.
